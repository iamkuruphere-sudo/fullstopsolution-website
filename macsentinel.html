Honest Architectural Principles: Evidence to Inspect, Not Automatic Verdicts

Unlike commercial antivirus tools that make dubious claims of "100% clean bills of health" or inject high-privilege kernel drivers, MacSentinel is designed with rigorous cryptographic honesty:

  • No System Changes: It never deletes files, alters system settings, modifies preferences, or quaran­tines software.
  • No Background Daemons: It runs only when you open it. When you close the app, zero background processes remain running.
  • Evidence vs. Verdicts: Legitimate applications routinely use launch services, network sockets, TCC permissions, and update helpers. Items flagged in MacSentinel are factual evidence for human review, not definitive accusations of malware.
  • Zero Telemetry: All audits execute 100% locally in user space memory. No telemetry, machine identifiers, or logs are ever transmitted to our servers or third parties.
  • Ad-Hoc Signed: Distributed as an open-source ad-hoc signed build for local inspection. Inspect the full Swift source code on GitHub anytime.
Always review security findings with a trusted security professional before deleting or modifying operating system components.

What MacSentinel Audits On Your Workstation

A comprehensive, point-in-time inspection across six critical macOS security surfaces.

🛡️

1. System Integrity & Security State

Audits low-level macOS security boundaries including System Integrity Protection (SIP), Gatekeeper policy, FileVault volume encryption, Secure Boot telemetry, and Mobile Device Management (MDM) enrollment profiles.

Checks: csrutil • spctl • fdesetup • enrollment
🌐

2. Network Listeners & Active Sockets

Catalogs all active TCP listeners, established socket connection tables, system proxy configurations, Application Firewall state, and active network sharing services (SMB, AFP, WebDAV).

Checks: TCP socket table • proxy • firewall • shares
⚙️

3. Persistence & Launch Daemons

Inventories primary macOS autostart locations: System & User LaunchDaemons, LaunchAgents, login background items, system extensions, and managed configuration profiles.

Checks: /Library/LaunchDaemons • LaunchAgents • extensions
📦

4. Application & Office Autoloaders

Inspects conventional Microsoft Office startup and template directories where macro or add-in autoloading can occur, and verifies application signature validity and quarantine attributes.

Checks: Office startup folders • code signing • quarantine
📜

5. Unified Log Forensic Queries

Interrogates the native macOS Unified Logging system (`log show`) for recent security-relevant events, privacy permission (TCC) changes, software update activity, and installer package history.

Checks: log show • TCC updates • install.log • signatures
💾

6. Local Audit Logs & JSON Export

Integrated with CocoaLumberjack for daily rotating local log files (retained up to 7 days). Provides explicit, user-triggered JSON report export for external auditing or compliance records.

Checks: DDFileLogger • daily rotation • explicit JSON export

Terminal Installation & Cryptographic Verification

How to verify the DMG package checksum and launch MacSentinel locally.

Step 1: Download & Verify SHA-256 Checksum

Open Terminal and verify that the downloaded disk image matches the official release hash: 

shasum -a 256 ~/Downloads/MacSentinel-arm64.dmg

Expected output: 060f124de7d888b03550b42c8b011b3e8884e44dbe0acd49946252e4ff0016d3

Step 2: Mount Disk Image & Install

Double-click MacSentinel-arm64.dmg and drag MacSentinel.app to your Applications folder.

Step 3: First Launch & Gatekeeper Notice

Because MacSentinel is an open-source, ad-hoc signed community build rather than an Apple-notarized commercial binary, macOS Gatekeeper may present a security prompt on initial launch. You can open it by:

  • Right-click MacSentinel.app in Finder and select Open, then click Open Anyway.
  • Or remove the download quarantine flag via Terminal: 
    xattr -dr com.apple.quarantine /Applications/MacSentinel.app

Step 4 (Optional): Full Disk Access for Deep Forensic Analysis

MacSentinel runs cleanly in user space out of the box. However, modern macOS privacy permissions hide certain internal log entries and TCC databases unless the app is granted Full Disk Access. To inspect restricted system areas: open System Settings → Privacy & Security → Full Disk Access and toggle on MacSentinel.

Frequently Asked Questions

Technical answers regarding MacSentinel's architecture and privacy.

Why is MacSentinel strictly read-only?

Automated remediation tools often inadvertently break legitimate system launch agents, corrupt enterprise configurations, or cause system instability. MacSentinel adheres to standard digital forensics best practices: gather accurate, uncompromised evidence first, and leave remediative decisions to the user.

Does MacSentinel transmit any data over the internet?

No. MacSentinel has zero network egress. It contains no tracking SDKs, no analytics pings, no cloud reporting backends, and no update daemons. All operations and audit logs are stored strictly on your local disk.

Can I inspect and compile the app from source?

Yes! The full Swift and SwiftUI codebase is available under the open-source repository at github.com/iamkuruphere-sudo/MacSentinel. You can build and run it directly using Xcode or via Terminal with swift run.
